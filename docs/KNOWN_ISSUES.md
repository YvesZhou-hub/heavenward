## Remaining implementation and compatibility limitations

- **Save migration and concurrency:** Version 1 saves are validated and mirrored; incompatible versions are rejected. There is no implemented migration from a previous shipped schema. Web Locks serializes same-origin saves when available; the optimistic fallback cannot guarantee atomic cross-tab writes without that API. Tests cover controlled corruption and interruption cases, not every native storage environment. Local data is intentionally not cheat-proof. Cloud saving is an interface boundary only and is presented as local-only. See `save.ts` and `PACING_QA.md` (master §13/15).
- **Replay scope:** Current-version combat replay now exists in `src/game/replay.ts` and `scripts/replay.ts`, with a real card/choice/turn test and full-state comparison. It requires the original opening configuration and accepted actions; a final diagnostic snapshot alone cannot reconstruct unknown opening HP. Current snapshots and the run journal support investigation. No cross-version full-run replay tool or compatibility migration is claimed (master §13).
- **Guidance and decision-UI acceptance:** The menu/settings Field Guide now contains three bilingual lessons with questions, three advanced rules references and two earned lore passages, alongside the two first-combat tips. Deck and combat-pile inspectors now expose Path/search filters through `DeckBrowser`; target previews display the resolver's multi-hit sequence as well as HP/Armor loss. These implementation gaps are resolved. Their final bilingual browser/editorial/usability acceptance belongs in the lead's QA record (master §9–10).
- **Summary depth:** Cosmetic cardbacks are selectable, discoveries/History persist, and `tribulation-lore` / `spirit-realm-lore` now reveal readable stories in the Field Guide. The summary shows selected counters and History duration; the source's optional detailed Immortal/Divine/archetype/cause breakdown is not fully presented (design §39–40; master §3/22).
- **Later Worlds:** Spirit Realm and Immortal Realm are intentionally future gameplay, not unfinished playable V1.0 routes. Human Realm Ascension ends the current run. This exclusion must remain clear in menus and release wording (design §2/43/47; master §1/3).
